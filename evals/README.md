# 评测集说明（`evals/`）

> 一句话：**50 条题，三种真值，三层指标。** 真值全部来自 `data/raw/` 原文和 MySQL 真实行，没有一条是「我觉得答案应该是这样」。

---

## 一、为什么是这 50 条

评测集不是「随便出 50 个问题」，而是**按 Agent 的分支结构切片**，保证每条链路都有样本、且比例接近真实流量。

| 类别 | 条数 | 考的是什么 | 判分靠什么 |
|---|---|---|---|
| `document` | 20 | RAG 召回 + 原文事实抽取 | 是否召回预期文件 + 关键事实是否出现 |
| `structured` | 10 | 路由到 SQL + 工具选对 + 参数对 | 是否调了预期工具 + 关键字段是否正确 |
| `hybrid` | 6 | 两条线都要走，且不能互相污染 | 文件召回 + 结构化事实同时成立 |
| `planning` | 8 | 个性化规划（要带学生画像/年级） | 路由对 + 回答里出现该场景的核心概念 |
| `general` | 6 | 闲聊与**知识库外**问题 | 路由对 + 该拒答的确实拒答了 |

**难例是刻意埋的**，这决定了评测集有没有用：

1. **同名文件多版本**：国家奖学金有 2024 和 2025 两份，问「2025 年名额」必须命中 45、问「2024 年」必须命中 42。答错年份是最典型的 RAG 事故。
2. **数值密集**：金额、名额、分数（8000 / 45 / 320 / 425 / 16000），错一位就是事故。
3. **知识库外问题**：「校长是谁」「食堂几点开门」——正确答案是「未检索到」，不是编一个。
4. **跨文档同义**：「四六级」在库里写作「全国大学英语四级考试（CET-4）」，考同义词映射有没有生效。
5. **需要跨两条线**：「找竞赛通知 + 报名截止时间」，只走 RAG 会缺时间，只走 SQL 会缺原文。

## 二、一条用例长什么样

`cases.jsonl` 每行一个 JSON：

```json
{
  "id": "D02",
  "category": "document",
  "question": "2025年国家奖学金我们学校有多少个名额？",
  "expected_route": "document",
  "expected_titles": ["关于做好2025年国家奖学金评选工作的通知"],
  "must_contain": ["45"]
}
```

| 字段 | 含义 | 用在哪一层 |
|---|---|---|
| `expected_route` | 应该走哪个分支 | 路由层、端到端 |
| `expected_titles` | 应该召回哪份文件（可给多个可接受答案） | 召回层、端到端 |
| `must_contain` | 回答里必须出现的事实 | 端到端 |
| `expect_tool` | 必须调用的工具名 | 端到端 |
| `expect_refusal` | 该拒答（知识库外） | 端到端 |

真值来源：`expected_titles` 来自 `data/raw/` 的文件名与 `document` 表；`must_contain` 逐条从原文条款里摘（例如「每人每年 8000 元」「名额 45 名」），结构化题来自 `competition` / `exam` 表真实行（例如蓝桥杯 2025 的 `signup_start = 2024-11-27`）。

## 三、三层指标，各回答一个问题

### 第 1 层：召回（`--layer retrieval`）

> 问：**该找到的文件，找到了吗？**

不调对话模型，只跑 `search_documents(question, k=5)`，几十秒跑完，几乎不花钱。

| 指标 | 定义 | 为什么看它 |
|---|---|---|
| **hit@5** | 预期文件是否出现在 top-5 里 | RAG 的天花板。召回不到，后面写得再好也没用 |
| **MRR** | 预期文件排名的倒数均值（第 1 名=1，第 3 名=0.33） | 区分「勉强挤进第 5」和「稳稳第一」 |

### 第 2 层：路由（`--layer router`）

> 问：**该走哪条路，走对了吗？**

只调 `classify()`，每题一次短 LLM 调用。

| 指标 | 定义 |
|---|---|
| **accuracy** | `plan.route == expected_route` 的比例 |
| **混淆矩阵** | 行=应有，列=实际。看系统性误判，不看单条 |

混淆矩阵比准确率有用：如果 `planning → document` 集中出现，说明 prompt 里「个人情况走 planning」这条规则没被模型吃住。

### 第 3 层：端到端（`--layer e2e`）

> 问：**最终那句话，能信吗？**

跑完整 LangGraph，一次 `run_agent()`。最贵，但只有这层能发现「路由对了、召回对了、答案还是错」的问题。

| 指标 | 定义 | 抓什么 |
|---|---|---|
| **路由准确率** | 同上，但在真实链路里 | — |
| **事实通过率** | 该题所有 `must_contain` 都出现的比例 | 硬伤：金额/名额/日期错 |
| **事实覆盖率** | 命中事实数 / 应命中事实数（按题加权） | 部分正确也算分，看整体水位 |
| **引用率** | 需要文件的题里，回答含 `[资料N]` 的比例 | 幻觉的廉价探针：不带引用多半在凭记忆答 |
| **工具命中率** | 应当调工具时真的调了预期工具 | 路由对了但没执行，等于没走 |
| **拒答率** | 知识库外问题里，明确说「不知道」的比例 | 最能体现「不装懂」 |
| **P50 / P95 延迟** | 端到端耗时 | P95 才是用户体验的真实水位 |

## 四、事实匹配是怎么做的（以及为什么不用 LLM 当裁判）

`run_eval.py` 里的 `contains()`：

1. **先归一化**：去掉空格、连字符、`年月日`。于是 `2024-11-27`、`2024 年 11 月 27 日`、`2024/11/27` 会压成同一个串 `20241127`，避免因为格式差异误判为「答错」。
2. **纯数字加边界**：`45` 只在左右都不是数字时才算命中，否则 `4500` 会把 `45` 骗过去。
3. 非数字（如 `CTF`、`一人一题`）直接子串匹配。

**为什么不用 LLM 当裁判**：两个原因。

- **可复现**：字符串匹配的结果是确定的，任何人重跑都一样；LLM 裁判每次可能不同。
- **可解释**：报告里能直接写「缺了 `425`」，而不是「模型认为不够忠实」。面试时前者能答，后者答不了。

代价是它只能测**可枚举的事实**，测不了「这段话讲得清不清楚」。所以这份评测测的是**正确性下限**，不是**表达质量**。

## 五、怎么跑

```bash
# 只测召回（最快，几乎不花钱）
python evals/run_eval.py --layer retrieval

# 只测路由
python evals/run_eval.py --layer router

# 端到端（最贵，约 3~5 分钟）
python evals/run_eval.py --layer e2e --concurrency 3

# 三层全跑
python evals/run_eval.py --layer all

# 冒烟：只跑前 3 条，改完 prompt 先这么验
python evals/run_eval.py --layer all --limit 3
```

产物：

```
evals/results/
├── eval_<tag>.json    逐题原始结果（含完整回答，便于回看）
├── report.md          人读报告：总览 / 混淆矩阵 / 失败清单
└── partial_*.json     每层跑完就落盘，长跑中断不丢
```

**跑之前务必确认**：Chroma 向量库必须可写。Chroma 以读写方式打开 SQLite，只读挂载会直接报
`attempt to write a readonly database`。沙箱环境要给 `var/` 写权限。

## 六、改完之后怎么用这份评测

一次标准的迭代闭环：

1. 改 prompt / 切片 / 路由规则；
2. `--layer retrieval` 先看召回有没有退化（十几秒）；
3. `--layer router` 看路由有没有被带偏（一分钟）；
4. `--layer all` 跑全量，对比上一次 `eval_*.json`；
5. **看失败清单，不看总分**。总分涨 2 个点可能是运气，失败清单里冒出的新问题才是真的。

**一条铁律**：每次线上发现 badcase，把它加进 `cases.jsonl`。评测集只增不减，它是回归网，不是成绩单。

## 七、这份评测的局限（面试被问要主动说）

1. **规模小**：50 条能发现系统性问题，不能给出置信区间很窄的指标。
2. **字符串匹配不是语义判断**：模型换个说法说对了，也可能被判错；反过来，关键词蒙对但逻辑错，会被判对。所以它是**下界**。
3. **单轮**：没有多轮追问、指代消解、上下文压缩的样本——这块要另建一套。
4. **数据是仿真的**：21 份文档是造出来的，真实学校的文档噪声大得多（扫描件、表格、附件）。
5. **没有覆盖成本**：只测了延迟，没统计 token 消耗。要算钱得在 `run_agent` 里挂 callback 统计 usage。
